## 数据结构

JDK 1.8 中 `HashMap` 的底层是 **数组 + 链表 + 红黑树**：

- 数组 `Node<K,V>[] table`，每个位置叫一个**桶（bucket）**
- 哈希冲突时，同一个桶里的元素用**链表**串起来
- 链表长度 ≥ 8 且数组长度 ≥ 64 时，链表转为**红黑树**；树节点 ≤ 6 时退化回链表

```java
static class Node<K,V> implements Map.Entry<K,V> {
    final int hash;
    final K key;
    V value;
    Node<K,V> next;
}
```

## hash 扰动函数

```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

高 16 位与低 16 位异或，让高位也参与下标计算，减少冲突。下标计算：`(n - 1) & hash`。

## put 流程

1. table 为空则先 `resize()` 初始化（默认容量 16）
2. 计算下标，桶为空则直接放入
3. 桶不为空：
   - key 相同 → 覆盖 value
   - 是树节点 → 插入红黑树
   - 否则遍历链表**尾插**，长度达到阈值时树化
4. `++size > threshold` 时扩容

## 扩容机制

- 负载因子 `loadFactor = 0.75`，阈值 `threshold = capacity * 0.75`
- 扩容为原来的 **2 倍**
- 元素新位置要么是**原位置**，要么是**原位置 + 旧容量**，通过 `(e.hash & oldCap) == 0` 判断，无需重新计算 hash

### 为什么容量是 2 的幂次方？

因为此时 `(n - 1) & hash` 等价于 `hash % n`，位运算更快，并且能让元素分布更均匀。

## 常见面试题

| 问题 | 要点 |
| --- | --- |
| HashMap 线程安全吗？ | 不安全，多线程用 `ConcurrentHashMap` |
| 1.7 和 1.8 的区别 | 1.7 头插法（并发扩容可能成环），1.8 尾插法 + 红黑树 |
| key 可以为 null 吗？ | 可以，hash 为 0，放在下标 0 |
| 为什么重写 equals 要重写 hashCode？ | 保证相等的对象落在同一个桶里 |

> 小结：记住“数组 + 链表 + 红黑树、0.75、2 倍扩容、8 和 64”这几个关键数字。
